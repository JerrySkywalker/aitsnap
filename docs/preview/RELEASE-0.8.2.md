# AITSnap 0.8.2 显示兼容修正

修复部分本机/虚拟显示驱动下整个窗口发黑、无内容的问题。0.8.0/0.8.1自动使用Windows窗口捕获排除；本轮同机蓝绿窗口对照由Owner确认：普通窗口正常，启用排除的窗口发黑，且应用仍能响应、完成Qt绘制。问题不等于程序没有启动。

默认改为兼容显示，不自动开启窗口内容排除；正式截图先隐藏主窗、迷你窗及实时图窗，等待合成器同步后重新采集，再恢复此前的窗口状态，不主动抢前台。仍保存原图/拼图、序号与既有三动作语义。

实时预览遇AITSnap自身遮挡时，仅对受影响来源提示移开窗口，其他来源继续；不会用黑块或自己的界面充当来源图像。需要完整的实时来源时，将主窗/图窗移出对应来源区域。此兼容退化与首次启动黑屏不同，界面本身仍正常显示。

“设置→外观”新增兼容显示选项，默认开启、下次启动生效。关闭后使用旧的Windows排除模式；仅在实际显示验证正常的环境使用。若自行关闭后出现黑屏，可用`aitsnap.exe --compatible-display --show`临时恢复正常显示，再保存外观设置；启动参数不自动改写原设置。老配置自动默认开启兼容，不需要删除区域/拼图或迁移输出。

版本0.8.2、schema5沿用，增加appearance.compatibleDisplay可选布尔项；缺省为true。0.8.1热键冲突恢复及0.8.0四项功能保留。目标平台/Word与安装器/人工验收仍按对应交付回执给出实际范围。

显示器布局现在只绘制当前活动显示器，不再把历史校准屏幕合并为仍在连接的屏幕。显示器接入、断开、位置、分辨率和DPI变化触发刷新；没有活动显示器时显示空状态，历史区域及方案保持。

“源区域”增加组合绑定状态、自动恢复开关、确认并绑定、解除绑定。显示器身份、物理布局与方向共同区分组合；应用记忆组合对应的方案和区域快照，同一个方案也能记忆不同组合的区域。已知组合在空闲且没有未保存设置时恢复；编辑或截图中延后，陌生组合保持原方案并提示核对。首次可从已有方案的校准记录接纳历史组合；从未确认过的双屏布局需核对区域后点击“确认当前布局并绑定此方案”。

记忆独立存于配置目录的`display-layouts-v1.json`。解除绑定会保留方案、截图和报告；被删除方案不会被自动恢复复活。显示器身份被驱动重新分配或记忆文件损坏时明确提示，不猜测硬件匹配。双屏实机与四屏模拟验证分开记录，真实四屏热插拔仍需相应硬件。

交付前必须在最终源码/二进制上通过原生截图和真实产品操作的文件回读测试；截图测试未通过时禁止打包。
