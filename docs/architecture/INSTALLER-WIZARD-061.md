# 0.6.1 installer wizard and scene proportions

The 0.6.0 owner installation succeeded (Windows Installer status0 and113matching payload hashes), but had no authored welcome/finish dialogs or launch action. This was a missing interaction flow. 0.6.1 adds the Chinese native MSI wizard requested by Owner: software/version welcome, destination editing and folder browsing, progress, terminal success/failure/cancel messages, launch-now choice and maintenance repair/uninstall. Only the successful UI Finish button may publish MsiLaunchApp, guarded against removal; quiet execution has no launch action. File references are quoted for paths containing spaces. Localization uses a936string pool and2052package language. MSI transaction/payload handling remains native.

The initial pilot created its welcome page. Its retained log then reported2810when entering the folder page: tab-order links had two predecessors to Next. The graph was corrected; a regression reading actual MSI Dialog/Control tables fails on that pilot and passes corrected authoring. It additionally checks Chinese/version text, path validation event, terminal UI sequence and guarded UI-only launch. Such checks do not prove visible layout or successful clicking.

Computer Use refused control of msiexec.exe with `product policy blocks this app: msiexec.exe`. No alternate UI injection or proxy control was used. Native full click-through, folder browsing and launch-checkbox execution must therefore retain HOLD until genuine attended evidence is available. Quiet install success cannot clear this gate. Final package/hash/runtime evidence is recorded in ignored WIZARD-061 receipts; release qualification is not asserted.

Scene investigation found two distinct semantics. The editable destination frame is intentionally independent of the image's ratio: actual sources/crops fit inside it with aspect preserved by default, potentially leaving margins. Explicitly disabling aspect fitting stretches the image. The editor and exported PNG share paintLayerLocal, so there is no separate intended image distortion in the editor.

Missing-source previews, however, always created a640x400placeholder regardless of the configured source region. This made wide/portrait selections look wrong before capture. New golden-pixel checks reproduce the mismatch against the old implementation, then pass with region/crop-proportioned bounded thumbnails. Placeholder thumbnails are not cropped again in source-pixel coordinates. The model, original capture dimensions, retained pixels and export semantics are unchanged. The aspect checkbox tooltip now describes fitting versus stretching. Qt6x64 and Qt5x64/x86 affected scene tests pass; unchanged capture/Word baselines are reused.

Windows10 native, Win7/Word2010 and human visual/layout qualification remain separate HOLDs. The original120-hour cumulative ledger continues without reset; historical packages and receipts stay immutable.
